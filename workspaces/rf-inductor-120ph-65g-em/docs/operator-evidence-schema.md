# Model assembly and qualification evidence

Use the corrected `passive-loss-r1` realization for final EM qualification.
The earlier positive direct-imaginary-permittivity results remain INVALID for
the passive design contract. Numerical agreement with those historical files
does not restore their validity. A physics-revision label is an operator
declaration; retain the input-validation reports, actual solver logs and source
receipts that establish it.

This page defines interfaces and completion rules. It reports no device result.

## 1. Assemble only compatible completed segments

Select the retained files for the same geometry, complete ordered N-port,
physical reference conductor, terminal planes, corrected materials and qualified
numerical representation. Record any different mesh or representation in its
control experiment rather than silently mixing it into the selected model.

Set these PowerShell variables to the selected files and a fresh output folder:

```powershell
$workspace = (Resolve-Path 'workspaces/rf-inductor-120ph-65g-em').Path
$actualLow = 'PATH_TO_COMPLETED_ACTUAL_LF.s2p'
$actualAfs = 'PATH_TO_COMPLETED_AFS_RAW_DISCRETE.s2p'
$actualValidation = 'PATH_TO_COMPLETED_INDEPENDENT_ACTUAL_CHECKS.s2p'
$denseAfs = 'PATH_TO_COMPLETED_DENSE_AFS_DERIVED.s2p'
$bundle = 'PATH_TO_FRESH_MODEL_BUNDLE'
```

The assembly command performs no interpolation, fitting, renormalization or
passivity repair. Actual points replace AFS-derived points only at exactly equal
parsed frequencies. Every actual/actual pair at a duplicate frequency must agree
within the frozen absolute complex-S limit. Do not loosen that limit to combine
incompatible attempts.

```powershell
python "$workspace/tools/combine_models.py" --segment actual $actualLow --segment actual $actualAfs --segment actual $actualValidation --segment AFS-derived $denseAfs --physics-revision passive-loss-r1 --output "$bundle/model.s2p" --receipt "$bundle/assembly.json"
```

Generate `assembly.json` with the tool; do not hand-author or edit its output
identity. Its minimum structure is:

| Field | Required content |
| --- | --- |
| `physics_revision` | `passive-loss-r1` for this corrected study |
| `port_count`, `reference_ohm`, `samples` | Complete model dimensions and real 50-ohm references |
| `source_segments` | Indexed source files, declared actual/AFS kind, sample count and integrity records |
| `point_provenance` | One entry for every output frequency, with selected kind, source segment index and original source sample index |
| `contains_AFS_derived_samples` | Consistent with the selected point kinds |
| `model_classification` | Explicit derived/composite classification whenever an AFS or derived DC point is selected |
| `duplicate_frequency_comparisons` | Selected source and the complete complex differences from other duplicate samples |
| `DC_anchor` | Explicit inclusion state and supporting evidence when enabled |
| `output` | Exact output identity generated by the tool |

Integrity values remain in machine-readable receipts. Original raw datasets,
raw Snp, AFS-derived data and solver settings remain authoritative evidence.

## 2. Compare the numerical controls

Every candidate point and every S entry participates. Exact reference frequency
matching is the default; no near-frequency grouping or partial comparison is
accepted.

```powershell
python "$workspace/tools/compare_networks.py" --reference $correctedFullStack --candidate $correctedCanonical --profile canonical --physics-revision passive-loss-r1 --output-dir $freshCanonicalComparison --csv
```

For an independently solved validation dataset, explicitly permit complex-S
linear interpolation of an AFS-derived dense reference only when needed. The
report retains its original bracket frequencies and weights and forbids
extrapolation. This reference value is never called an actual solve.

```powershell
python "$workspace/tools/compare_networks.py" --reference $denseAfs --reference-kind AFS-derived --reference-interpolation linear --candidate $actualValidation --profile afs --physics-revision passive-loss-r1 --output-dir $freshAfsComparison --csv
```

Use `mesh` for the adopted L/Q mesh comparisons and `reproduction` for the fresh
rebuild. The `port` and `return` profiles report sensitivities without inventing
acceptance limits. Their observed changes still belong in the uncertainty
budget. Source geometry/stack/port identity and material validity are separate
checks; a matching network does not establish them.

The AFS protocol also requires the declared exact boundaries and the independent
midpoints selected from actual adaptive-sample gaps. A comparison PASS does not
prove that the midpoint-selection rule was followed; retain that selection and
the original frequency arrays.

## 3. Complete the uncertainty and low-frequency evidence

Save the following JSON structure as `uncertainty.json` in the bundle. It is a
fill-in template, not completed engineering evidence: `null` quantities are
deliberately rejected, and false flags keep qualification incomplete. Replace
them only after reviewing the corresponding retained experiments. Paths in
`evidence_files` resolve relative to this JSON file.

```json
{
  "physics_revision": "passive-loss-r1",
  "L_absolute_pH": null,
  "coverage_10_65": false,
  "coverage_through_80": false,
  "checks": {
    "mesh": false,
    "port": false,
    "boundary": false,
    "material": false,
    "dc_low_frequency": false,
    "reproduction": false,
    "afs": false
  },
  "reactance_frequency_envelope": {
    "validation_kind": "actual-control-comparisons",
    "interpolation_rule": "interval-max-equivalent-L",
    "points": [
      {
        "frequency_hz": 10000000,
        "direct_X_absolute_ohm": null,
        "L_absolute_pH": null
      },
      {
        "frequency_hz": 80000000000,
        "direct_X_absolute_ohm": null,
        "L_absolute_pH": null
      }
    ],
    "evidence_files": [
      "controls/mesh/comparison.json",
      "controls/port/comparison.json",
      "controls/return/comparison.json",
      "controls/canonical/comparison.json",
      "controls/afs/comparison.json",
      "controls/reproduction/comparison.json"
    ]
  },
  "low_frequency_limit": {
    "status": "NOT_YET_ESTABLISHED",
    "first_actual_frequency_hz": 10000000,
    "inductive_limit_positive": false,
    "evidence_files": [
      "dc/dc-analysis.json",
      "controls/low-frequency-agreement.json",
      "controls/low-frequency-limit.json"
    ]
  }
}
```

Completion rules:

- `L_absolute_pH` is a supported conservative bound from observed numerical
  differences plus the adopted AFS interpolation reserve. The protocol reserves
  0.5% of the 120 pH target, or 0.6 pH; that reservation alone does not replace
  mesh, port, return, representation and frequency-validation evidence. It is
  not a manufacturing tolerance or a measured process distribution.
- Add all controlling actual validation frequencies to the envelope, in strictly
  increasing order. The two endpoints above show the minimum syntax, not a
  reason to discard an interior maximum. The first node must support the first
  claimed RF frequency and the last must cover 80 GHz.
- At each node, provide a supported absolute direct-reactance sensitivity and
  inductance bound. The tool takes the maximum of direct dX divided by `2*pi*f`,
  that node's dL, and the global dL. Between nodes it uses the larger endpoint
  equivalent-dL bound and computes dX at the current frequency. It records the
  bracket and does not extrapolate outside the control domain.
- Do not also supply `reactance_absolute_ohm` with this frequency envelope. Do
  not substitute zero uncertainty for missing controls. A large high-frequency
  absolute dX is not copied down to DC.
- The low-frequency-limit report must establish the positive inductance limit
  and consistency of the conductive/DC model with actual LF samples at the same
  terminal planes. DCR alone does not establish an inductive limit. Retain the
  representation, residuals, contact treatment and its supported interval.
  Only then set `status` to `SUPPORTED_BY_DC_AND_ACTUAL_LF` and
  `inductive_limit_positive` to true.
- Set each `checks`/coverage value true only when its supporting evidence is
  complete. `checks.afs` includes the independent exact/midpoint comparisons,
  their selection record and physical checks of actual and derived data
  separately. These flags are operator conclusions, not automated evidence.

## 4. Run final analysis with the explicit protocol

The analyzer verifies that the assembly receipt identifies the exact analyzed
file. It retains per-point provenance and requires actual sources for the exact
65/80 GHz evaluations, the protocol's other exact boundaries and LF probes.
AFS grid points cannot stand in for those actual solves.

```powershell
python "$workspace/tools/analyze_em.py" "$bundle/model.s2p" --assembly-receipt "$bundle/assembly.json" --protocol "$workspace/inputs/numerical-protocol-amendment-r2.json" --uncertainty-json "$bundle/uncertainty.json" --output-dir "$bundle/final-analysis"
```

The adopted protocol checks LF probes at 0.01/0.1/1/2/3/4/5 GHz, actual boundary
sources, at most 1 GHz spacing through 100 GHz and at most 5 GHz through 200 GHz.
Keep sampling/model-validity gaps explicit. The CLI without an explicit protocol
is characterization only. The original programmatic numeric interface remains
available for existing tests and must not be substituted for final qualification.

The current frequency revision also forces actual 20/40 GHz samples and includes
them in the independent exact-control run. It uses 48 adaptive plus six forced
plans within the unchanged combined cap of 54. This frequency revision does not
change the material realization named `passive-loss-r1`.

Read `device_target_result`, `gaps`, `final_qualification_status` and the per-point
source/error records together. Unresolved global evidence also prevents an
isolated criterion from appearing qualified. The parent filter remains
NOT EVALUATED by this single-device analysis.

## 5. Optional DC endpoint, after agreement is established

The default assembly has no zero-Hz point. If a DC endpoint is needed, retain
the independent sheet report and a separately completed LF agreement JSON with
this structure:

```json
{
  "state": "AGREEMENT_ESTABLISHED",
  "dc_resistance_ohm": null,
  "rf_frequency_hz": 10000000,
  "rf_resistance_ohm": null,
  "absolute_tolerance_ohm": null,
  "reference_planes_consistent": false,
  "contact_model_reviewed": false,
  "low_frequency_justification": "REPLACE_WITH_THE_SUPPORTED_LIMIT_AND_RESIDUAL_ARGUMENT",
  "evidence_files": [
    "PATH_TO_ACTUAL_LF_DATA_OR_ANALYSIS",
    "PATH_TO_CONTACT_AND_LOW_FREQUENCY_REVIEW"
  ]
}
```

The assembler checks the RF value against an actual selected sample under
Icm=0, its passivity/reciprocity and the declared agreement tolerance. Use a new
bundle and append these options to the assembly command only after completing
the evidence:

```powershell
--include-dc --dc-resistance-json $completedDcReport --lf-agreement-json $completedLfAgreement
```

The endpoint is explicitly a derived series-R realization with an open common
mode, not an EM simulation at DC. It does not automatically validate a consumer
simulator's interpolation between zero and the first RF frequency.
